## 결정

- TC 흐름: 화면 진입 → 값 입력 → 실행 → 결과 검증 → 다음 단계
- 기본 검증은 헤드리스로 실행하고, 사용자가 요청할 때만 브라우저 UI를 시연
- TC 정의·절차·기대결과·실행 이력은 `tests/test-cases/qa-test-cases.csv`에서 관리
- 실제 자동화 입력값과 검증값은 `tests/test-data/<menu>.yml`에서 관리
- URL과 계정 등 민감정보는 환경변수로만 관리
- 로그인 URL도 `PLAYWRIGHT_LOGIN_URL` 환경변수로만 주입
- 완료 작업은 로컬 커밋까지만 진행하고, 푸시는 사용자 요청 시 한 번에 수행
- TC 데이터는 YAML로 관리하되 실제 자격증명은 평문으로 저장하지 않음
- YAML 자격증명 필드에는 환경변수 참조명만 허용하도록 `AGENTS.md` 지침 보강
- 참고 프로젝트 형식에 맞춰 TC 문서 CSV와 자동화 데이터 YAML을 역할별로 분리
- TC CSV를 `tests/test-cases/`로 이동해 모든 테스트 자산을 `tests/` 아래로 통합
- 루트 `.env.example`을 `tests/test-data/`로 이동하고 비코드 테스트·환경정보 파일 저장 위치를 통일
- 수집 예약명은 기존 `수집테스트자동N`의 최대 숫자 다음 값으로 생성
- TC-003 입력값은 DB카탈로그/ORA19C(META42_DEV), 특정일 2036-08-31, 특정시 15시 30분으로 고정
